# Оператор: как лаборатория управляет тестовым счётом с вашего Mac

Этот файл для вас, владельца. Программа `operator.py` работает на вашем Mac в Сербии и выполняет решения
координатора лаборатории (облачной сессии Claude) по тестовому счёту Polymarket. Сам координатор заявки
отправлять не может: у него американский адрес, а Polymarket не принимает заявки из США. Поэтому решения он
записывает в git, а исполняет их ваш Mac, только в рамках, которые задали вы.

**Честно о деньгах.** Проверенной прибыльной стратегии у лаборатории пока нет: двадцать два замера закончились
без подтверждённого преимущества (`HANDOFF.md`). Программы, которые оператор запускает, — это маленькие опыты
с жёсткими пределами (например, `exp_bids.py` тратит не больше 15 pUSD в сутки). Оператор сам ничего не
зарабатывает: он делает так, чтобы решения лаборатории исполнялись, а убыток не вышел за ваши пределы. Сколько
денег можно потерять, решаете вы, в файле `ARMED` (ниже).

## Как это устроено

1. Координатор пишет решение в файл `control/desired.json` на ветке `live-control` репозитория на GitHub:
   номер команды (`seq`) и список действий.
2. Оператор на Mac раз в минуту скачивает эту ветку (`git fetch`) и читает **только этот файл**. Код с этой ветки
   он никогда не запускает и не подставляет в рабочую папку: запускаются только программы, которые уже лежат у вас
   в `pilot/`. Обновляете их только вы, руками (`git pull`).
3. Каждый номер команды выполняется один раз. Действие должно быть из короткого списка, с числами в
   разрешённых пределах. Всё остальное отклоняется и попадает в отчёт.
4. Живые действия (настоящие заявки) выполняются, только пока есть ваш файл `~/.polymarket-pilot/ARMED`.
5. После каждого действия и не реже чем раз в 30 минут оператор кладёт короткий отчёт на ветку `live-reports`
   и отправляет на GitHub. Координатор читает отчёт и пишет вам, как идут дела. В отчёте нет ключа, секретов,
   адреса кошелька, имени пользователя, имени компьютера и путей вашей домашней папки.

## Что нужно до первого запуска

- Папка `pilot/` настроена по `README.md`: есть `.venv`, ключ лежит в `~/.polymarket-pilot/key`,
  `.venv/bin/python smoke.py auth --live` показывает баланс.
- С этого Mac работает `git push` в репозиторий лаборатории (оператор отправляет отчёты на ветку
  `live-reports`; в `main` он ничего не пишет). Проверка: `git push --dry-run origin HEAD:refs/heads/live-reports`
  из папки репозитория.
- VPN выключен. Сербия не в списке стран, откуда Polymarket не принимает заявки (`NOTES.md`, раздел про
  геоблок); соблюдать правила площадки для своей страны — на вас.

## Запуск

```bash
cd polymarket-lab/pilot
.venv/bin/python -I operator.py selftest      # последняя строка: selftest: ALL PASS (около 10 секунд)
caffeinate -is .venv/bin/python -I operator.py run
```

Оставьте это окно Терминала открытым: оператор работает, пока оно открыто. В окне видно каждое событие
(`received`, `started`, `done`, `refused` и так далее).

**Чтобы Mac не уснул.** `caffeinate -is` не даёт ему уснуть, пока идёт оператор (ключ `-s` работает только от
сети). Поэтому: подключите зарядку, не закрывайте крышку ноутбука (закрытая крышка усыпляет Mac всё равно),
в «Системных настройках» → «Аккумулятор» → «Параметры» для работы от сети включите «Не переходить в режим сна
автоматически, когда дисплей выключен».

Если Mac всё-таки уснул: после пробуждения оператор продолжит сам. Старые команды он не повторит, а действия,
выданные больше 20 минут назад (или дольше, если координатор указал другой срок), пропустит и напишет об этом
в отчёте.

Запустить второй оператор нельзя: второй откажет (`another operator is running`).

## Как взвести (разрешить живые заявки)

Создайте файл руками:

```bash
cat > ~/.polymarket-pilot/ARMED <<'EOF'
max_total_loss_usd = 50
max_daily_loss_usd = 15
EOF
chmod 600 ~/.polymarket-pilot/ARMED
```

Числа здесь — пример, решаете вы. Что они значат:

| Строка | Смысл |
| - | - |
| `max_total_loss_usd` | сколько долларов можно потерять за весь опыт. Дошли — всё живое останавливается до вашего нового `ARMED` |
| `max_daily_loss_usd` | сколько можно потерять за одни сутки по UTC (в Белграде сутки меняются в 01:00 зимой, в 02:00 летом) |
| `baseline_balance_usd` | необязательно: с какого баланса считать опыт. Без этой строки берётся первый баланс, прочитанный после взведения. Пополнили счёт — допишите эту строку с новым балансом |
| `milestone_step_usd` | необязательно: шаг, на котором отчёт отмечает рост прибыли (по умолчанию 100). Вы просили сообщать каждые 200–500 евро — например, `milestone_step_usd = 250` |

Правила файла: только эти строки, числа в долларах (pUSD на счёте почти равен доллару), предел за весь опыт
от 1 до 300, предел за день не больше предела за весь опыт. Файл должен принадлежать вам и не быть доступным
на запись другим (`chmod 600`). Если что-то не так, оператор считает, что вы **не** взвели, и пишет причину
в отчёте.

Проверить, как оператор понял файл и сколько осталось до пределов:

```bash
.venv/bin/python -I operator.py status
```

## Как разоружить

```bash
rm ~/.polymarket-pilot/ARMED
```

В течение минуты оператор прерывает идущую живую программу (она сама снимает свои заявки) и больше живых
действий не начинает. Сухие прогоны, чтение баланса и отчёты продолжаются.

Координатор тоже может разоружить (действие `disarm`): тогда он переименовывает ваш файл в
`ARMED.disarmed-<время>`. Взвести снова координатор не может: это делаете только вы, создав `ARMED` заново.

## Как остановить всё

- **Мягко:** `touch ~/.polymarket-pilot/STOP`. Программы перестают ставить заявки, снимают свои, дописывают итоги
  и выходят; оператор не начинает новых запусков (сухих тоже), пока файл есть. Если через 15 минут программа
  всё ещё идёт, оператор прерывает её сам. Снять стоп: `rm ~/.polymarket-pilot/STOP` — это делаете только вы.
- **Сразу:** `Ctrl+C` в окне оператора. Он прерывает идущую программу (она снимает свои заявки), отправляет
  последний отчёт и выходит.
- **На сайте:** polymarket.com → открытые заявки → снять. Это работает всегда, даже если Mac выключен.

## Что значат пределы

Оператор считает убыток двумя способами и берёт **больший**:

1. **По балансу:** баланс pUSD на старте минус баланс сейчас. Баланс он читает сам (`smoke.py auth --live`)
   перед каждым живым запуском, после него и каждые 30 минут во время него. Выигрыш, который ещё не погашен
   (redeem, см. `EXPERIMENTS.md`), на балансе не виден, поэтому эта оценка осторожная: убыток может казаться
   больше настоящего. Гасите выигрыши на сайте, и оценка станет точной.
2. **По записям программ** (`pilot/out/exp-*.jsonl`): итог рассчитанных рынков плюс всё, что ещё под риском:
   купленные акции в нерассчитанных рынках и заявки без итоговой записи (они считаются исполненными целиком).

Когда убыток доходит до предела, оператор создаёт файл `STOP`, прерывает живую программу и пишет об этом в
отчёте. Живой запуск не начинается, если до предела осталось меньше одного шага программы (одно окно
`exp_bids` — до 5 долларов, одна ставка `exp_fav` — 5 или 10). Поэтому предел может быть превышен самое большее
на один шаг, который уже шёл в момент проверки.

После дневного предела `STOP` остаётся: на следующий день вы удаляете его сами, если согласны продолжать.
После предела за весь опыт новые живые запуски будут отклоняться, пока вы не напишете новый `ARMED` с другими
числами.

Координатор может **понизить** ваши пределы (действие `set_limits`), но не повысить. Понижение действует, пока
вы не перепишете `ARMED`: новые числа в файле — ваше новое решение, и с этого момента действуют они.

## Что координатор может и чего не может

| Может | Не может |
| - | - |
| запустить одну из программ из списка ниже с числами в разрешённых пределах | запустить что-то ещё: другую программу, другую команду, свои аргументы, команду оболочки, путь к файлу |
| запустить живую программу, пока `ARMED` есть, `STOP` нет и до пределов осталось больше одного шага | взвести счёт, повысить пределы, удалить `STOP` |
| понизить пределы, остановить всё (`stop_all`), разоружить (`disarm`) | запустить живое без `ARMED` или при `STOP` |
| попросить отчёт, прочитать баланс и открытые заявки | менять код на вашем Mac: оператор запускает только файлы, которые уже лежат в `pilot/` |
| | увидеть ключ или адрес кошелька: их нет в отчётах |
| | запустить две программы сразу: идёт одна, следующая ждёт |

Важно: писать на ветку `live-control` может любой, у кого есть доступ на запись в репозиторий на GitHub. Он
сможет то же, что и координатор (и не больше: тот же список и ваши пределы). Держите доступ к репозиторию
узким.

## Для координатора: формат файла команд

Файл `control/desired.json` на ветке `live-control`. Пример — `pilot/control-example.json`. Проверка файла до
отправки (без сети и без состояния): `python3 -I pilot/operator.py check control/desired.json`.

```json
{"seq": 7, "issued_utc": "2026-11-28T09:00:00Z", "note": "что и зачем",
 "actions": [{"id": "lt3", "program": "exp_bids", "cmd": "run",
              "params": {"config": "late-tail", "windows": 3, "live": true}, "max_age_min": 30}]}
```

- `seq` — целое, каждый раз больше прошлого; меньший или тот же номер не выполняется.
- `issued_utc` — время выдачи по UTC. Действие, которое не началось за 20 минут (или за `max_age_min`, до 360),
  пропускается. Время больше чем на 5 минут в будущем — отказ всей команды.
- Новая команда отменяет ещё не начатые действия прошлой. Одно недопустимое действие — отказ всей команды;
  выполняются только `stop_all`, `disarm`, `set_limits` из неё. Эти три выполняются и тогда, когда команда
  устарела.
- Действия по очереди; программа с `run` ждёт, пока закончится предыдущая. Короткие действия (status, auth,
  report) идут и во время неё.

| program | cmd | params | что запускается |
| - | - | - | - |
| `smoke` | `auth` | — | `smoke.py auth --live` (баланс, разрешения; без заявок) |
| `smoke` | `status` | — | `smoke.py status --live` (открытые заявки) |
| `smoke` | `cancel` | — | `smoke.py cancel --live` (снять заявки, поставленные `smoke.py`) |
| `smoke` | `selftest` | — | `smoke.py selftest` |
| `exp_bids` | `run` | `config`: `tails`, `pairs`, `late-tail`; `windows`: 1–36; `live`: true/false (по умолчанию false) | `exp_bids.py run --config experiments/<config>.json --max-windows N [--live]` |
| `exp_bids` | `report` | `dry_run`: true/false | `exp_bids.py report [--dry-run]` |
| `exp_bids` | `selftest` | — | `exp_bids.py selftest` |
| `exp_fav` | `run` | `ticket`: 5 или 10; `hours`: 1–12; `live`: true/false | `exp_fav.py run --ticket T --hours H [--live]` |
| `exp_fav` | `report`, `selftest` | — | `exp_fav.py report`, `exp_fav.py selftest` |
| `operator` | `set_limits` | `max_total_loss_usd`, `max_daily_loss_usd` (только ниже текущих) | встроено |
| `operator` | `stop_all` | — | файл `STOP`, прервать идущую программу, очистить очередь, `smoke.py cancel --live` |
| `operator` | `disarm` | — | переименовать `ARMED`, прервать живую программу |
| `operator` | `report` | — | отчёт сейчас |

Все программы запускаются как `.venv/bin/python -I -B -u pilot/<программа>.py ...` из папки `pilot/`.

**`exp_fav.py`** появился 27.11 вечером, его ещё дописывает и проверяет другой агент. Его команда
`run [--live] [--ticket T] [--hours H]` совпадает с таблицей (сверено по `exp_fav.py run --help`). Перед первым
запуском каждой новой версии любой программы с `run` оператор снова проверяет её `--help`: если там нет нужных
ключей, запуск отклоняется с причиной «command line differs», и оператор нужно поправить. Записи `exp_fav.py`
(`out/exp-fav-*.jsonl`: строки `decision`, `order`, `result`) оператор читает по их собственным правилам:
исполнение с неизвестным итогом считается потерей всей ставки, нерассчитанная сделка — под риском целиком.

## Отчёты

Ветка `live-reports` на GitHub, папка `reports/`:

- `latest.md` — коротко по-русски: взведён ли счёт, есть ли STOP, пределы и сколько до них осталось, баланс,
  итог, последние события с выводом программ;
- `latest.json` — то же для координатора;
- `events.jsonl` — последние 200 событий без вывода программ.

Отчёты пишутся из отдельной рабочей папки `~/.polymarket-pilot/reports-worktree` от имени `pm-operator`, так что
ваша папка с кодом не меняется, а ваше имя не попадает в историю. Каждый отчёт — отдельный коммит.

Если отчёт не ушёл (нет сети), оператор пробует снова каждую минуту; события не теряются.

## Где что лежит на Mac

| Путь | Что это |
| - | - |
| `pilot/operator.py` | запуск оператора (маленький файл: его имя совпадает со стандартным модулем Python `operator`, и он устроен так, чтобы `smoke.py` и `exp_bids.py` работали рядом с ним как прежде) |
| `pilot/pm_operator.py` | код оператора |
| `~/.polymarket-pilot/ARMED` | ваше разрешение и пределы (создаёте вы) |
| `~/.polymarket-pilot/STOP` | стоп для всех программ |
| `~/.polymarket-pilot/operator-state.json` | состояние: последний номер команды, баланс на старте, события |
| `~/.polymarket-pilot/operator-logs/` | полный вывод каждого запуска (только у вас, в отчёт идёт очищенный хвост) |
| `~/.polymarket-pilot/reports-worktree/` | рабочая папка ветки отчётов |

Удалять `operator-state.json` не нужно: без него оператор забудет номер последней команды (на этот случай
старые команды всё равно отсекаются по возрасту).

## Обновление кода

Только вы: остановите оператор (`Ctrl+C`), `git pull`, `.venv/bin/python -I operator.py selftest`, запустите
снова. Оператор сам код не обновляет никогда.

## Что проверено и что нет

Проверено в облаке 27.11.2026 на временных репозиториях и подставных программах (`pilot/verification-operator-2026-11-27.txt`):
список действий и пределы чисел, однократное выполнение команд и отсутствие повторов после перезапуска,
устаревшие и «будущие» команды, сон, `ARMED` и пределы убытка (остановка по дневному пределу), `STOP`,
`stop_all`, `disarm`, очистка отчётов, отправка на ветку отчётов, нетронутая папка с кодом. Настоящие
`smoke.py` и `exp_bids.py` рядом с `operator.py` проходят свои самопроверки.

Не проверено: живые запуски настоящих программ, `git push` с вашего Mac на GitHub, работа `exp_fav.py`
(его ещё нет), поведение на macOS при настоящем сне. Первый раз смотрите за отчётом и окном Терминала сами.
