Ты строишь живую часть проекта polymarket-lab на этом Mac (Сербия): запись цен в реальном времени, бумажную торговлю и модуль заявок. Репозиторий: https://github.com/alloben812/polymarket-lab. Замеры на истории ведут другие исполнители, их файлы не трогай.

ЗАЧЕМ. Владелец хочет торговать на Polymarket маленькой суммой (пара сотен евро) с этого Mac. Замеры на истории показывают, есть ли преимущество. Твоя часть показывает, достижимо ли оно вживую, и даёт безопасный способ слать заявки.

СНАЧАЛА ПРОЧИТАЙ ЦЕЛИКОМ:
1. AGENTS.md — правила и запреты, они обязательны.
2. NOTES.md — проверенные факты о площадке, комиссии, инструменты pmlab. Ограничения облачной песочницы оттуда к этому Mac не относятся.
3. studies/gaps/btc5m_lockin/protocol.md и results.md — единственное правило с проверенным положительным числом; оно будет первой стратегией в бумажном режиме.
QUEUE.md и docs/astra-start.md описывают старый план: задания A-* не бери.

ТВОЯ ЗОНА. Папка live/ и одна ветка astra/live от main, один PR в main (не вливать). Вне live/ ничего не меняй, включая HANDOFF.md, QUEUE.md, pmlab/ и studies/: их правят другие агенты, будут конфликты. Зависимости — в live/requirements.txt. Состояние веди в live/STATUS.md четырьмя блоками: Сейчас / Сделано и чем доказано / Дальше / Вопросы владельцу.

ЗАДАНИЯ, по порядку, одно за раз:

L-0. Окружение. Клон, python3 -m pip install -e ., python3 -m pytest -q tests (ожидаемо 8 passed). Проверь с этого Mac: публичный REST Polymarket отвечает; WebSocket рыночного канала отдаёт поток сообщений; проверка геоблокировки из официальной документации говорит, что страна не закрыта; часы Mac синхронизированы. IP-адрес никуда не записывай. Результат — в live/STATUS.md.

L-1. Запись. Программа пишет стакан и сделки по списку рынков из конфига (для начала: текущие окна BTC up/down 5m и 15m, дневные погодные рынки, теннисные матчи дня) с локальным временем приёма в сжатые файлы в data/live/ (папка не в git). Переподключение, обнаружение разрывов, команда status. Готово когда: 2 часа записи без незамеченных разрывов; из записи восстанавливается стакан на любой момент; есть тесты на записанном образце.

L-2. Бумажная торговля. Стратегия получает события стакана и сделок и выдаёт намерения. Исполнение моделируется консервативно (правило 4 исследований из AGENTS.md): только по показанной цене и размеру, с задержкой; пассивная заявка считается исполненной, только когда сделка прошла сквозь её цену. Комиссии — из pmlab.fees. Каждое решение пишется в журнал вместе со снимком данных. Ежедневная сводка: число сделок, результат после комиссий, сравнение с ожиданием из замера. Готово когда: повторный прогон по той же записи даёт тот же результат; правило btc5m_lockin работает в бумажном режиме на живом потоке.

L-3. Модуль заявок, по умолчанию «всухую». Только официальный SDK; имя пакета возьми из docs.polymarket.com (в поиске есть подделки, крадущие ключи). Ключ читается из локального файла вне репозитория или из Keychain и никогда не попадает в журнал, git и чат. Лимиты в коде: размер заявки, суммарная позиция, дневной убыток, белый список рынков, файл-стоп. Готово когда: есть тест на каждый лимит и сквозной прогон всухую. Живая проверка (одна пассивная заявка далеко от рынка: поставить и снять) — только по отдельному слову владельца и при нём.
