# Живая лаборатория

Команды выполняются в корне клона polymarket-lab. Рабочее окружение проверено на Python 3.12. Большие файлы остаются в data/live/ на этом компьютере.

```sh
python3.12 -m venv live/.venv
. live/.venv/bin/activate
python3 -m pip install -e . -r live/requirements.txt
python3 -m pytest -q tests live/
python3 -I live/doctor.py
caffeinate -i python3 -m live.record record --seconds 7320
python3 -m live.record status
```

У каждой записи своя папка с UTC-временем старта. Настройки рынков лежат в live/markets.json. Регистратор подписывается на текущие и следующие окна BTC 5m/15m, температурные корзины Лондона, Парижа и Нью-Йорка и до десяти матчей дня по календарю тенниса (сначала уже начавшиеся). Он получает стаканы, изменения уровней и публичные сделки. В тех же файлах сохраняются доступные в момент наблюдения закрытые секундные свечи BTCUSDT и официальные выплаты по завершившимся рынкам.

Каждая строка содержит время приёма на Mac в наносекундах и локальный порядковый номер. Это время получения сообщения приложением. Если время в данных площадки отличается, сохраняются обе отметки. Данные сжимаются блоками; завершённая минута получает окончательное имя после сброса на диск. Статус отражает подтверждённые сервером PONG, сетевые ошибки и сверки. Оставшаяся после аварии часть .open может быть неполной. Команда validate проверяет запечатанные минуты и считает по каждому полностью записанному окну BTC долю времени с пригодной глубиной для каждого исхода. Счётчик binance_declared_missing_seconds показывает пропуски секундных свечей, явно ограниченные в записи. Их нужно исключать из расчётов. Пропуск без подходящих границ считается ошибкой архива. Снимок, полученный до начала окна, учитывается лишь пока соответствующий стакан остаётся доступен.

```sh
python3 -m live.validate "$RUN_DIR" --minimum-seconds 7200
python3 -m live.book as-of "$RUN_DIR"/*.jsonl.gz --token "$TOKEN" --recv-ns "$AT_NS" --depth 3
python3 -m live.book coverage "$RUN_DIR"/*.jsonl.gz --token "$TOKEN"
```

Для команд выше RUN_DIR — папка конкретного сеанса, TOKEN — публичный идентификатор исхода из строки market, AT_NS — интересующий момент в Unix-наносекундах. Внутри интервала потери связи цена помечается недоступной. Изменение биржевого времени назад, несовпадение глубины и отсутствие начального снимка также закрывают покрытие. Новый пригодный полный снимок восстанавливает его. Для неподвижной книги используется подтверждение связи. В активном стакане сверка REST учитывается только когда за время запроса не поступало изменений этого токена. Площадка не предоставляет сквозного номера своих сообщений, поэтому отдельная пропущенная и затем компенсированная дельта может остаться ненаблюдаемой. Описанные проверки измеряют покрытие, которое можно доказать из записи.

## Бумажная торговля

```sh
python3 -m live.paper live --seconds 600 --latency-ms 1000 --cash 200
python3 -m live.paper replay "$RUN_DIR" --output data/live/paper-repeat
```

Первая команда печатает папку нового сеанса. Запись идёт на Mac. В подпапке paper появляются decisions.jsonl и daily.json. Вторая команда обрабатывает запечатанную запись по тем же правилам и пишет результат в новую папку. Параметры задержки и бумажного капитала должны совпадать, если требуется побайтовое сравнение. Сводка обновляется во время работы и при остановке. Время дней — UTC.

Стратегия btc5m_lockin оценивает публичные сделки в последнюю минуту окна BTC 5m. Сигнал использует только полученные к этому моменту закрытые секундные свечи. Вариант из исследования требует вероятности от 0,99, запаса в цене 0,02 и расстояния от страйка не меньше 18,6294 доллара. Для покупки нужен подтверждённый ask с показанным объёмом. Размер ограничен объёмом сделки-сигнала, глубиной, виртуальным капиталом, 100 долями на попытку и 500 на рынок. У общей модели пассивная заявка может исполниться только после встречной публичной сделки строго за ценой заявки. У такера применяется комиссия pmlab.fees. В демонстрации используется виртуальный капитал 200 расчётных единиц и задержка исполнения 1000 мс сверх модельной информационной задержки.

Каждое рассмотренное решение в последнюю минуту оставляет запись с причиной, доступными данными и номером строки исходной записи. Сводка учитывает сумму комиссий и реализованный результат в день продажи или официального расчёта. Стоимость открытых позиций показана отдельно. При обнаруженном задним числом разрыве, который затронул исполнение, итог с этого дня помечается недоступным. Сравнение с историческим результатом +3,58 цента на долю (5 рынков контрольной выборки) появляется после закрытия позиции. При нуле исполнений доходность на долю не определена.

## Модуль заявок

```sh
python3 -m live.orders canary --request-id first-dry-check
python3 -m live.orders status
```

По умолчанию команда целиком на этом компьютере моделирует одну пассивную покупку и её снятие. При повторе с тем же идентификатором она показывает итог первого запроса. Сухая база SQLite и файл-стоп находятся в data/live/orders/. Существование файла STOP запрещает новую постановку. Снятие ранее поставленной заявки доступно и при STOP.

В коде заданы потолки в расчётных единицах pUSD. Номинал одной заявки до 1, совокупная экспозиция до 5, дневной риск до 2. В дневной риск входит уже реализованный убыток текущего дня UTC и максимальный убыток по открытым позициям и заявкам, включая неопределённые. Нерассчитанная позиция переносится через полночь. Это технические потолки проверки одной пассивной заявки. В сухом примере цена 0,05, объём 5 долей и номинал 0,25. Пара рынок–исход должна быть в списке разрешений. Цена проверки минимум на 0,05 и на пять шагов ниже лучшей цены покупки.

Для будущей живой проверки владелец отдельно задаёт рынок, исход, цену и объём, находится у Mac и подтверждает точные параметры в терминале. Команда canary требует режима --live, этих параметров, постоянного --request-id и локального --key-file. Используется уже выпущенный торговый Session Key для Deposit Wallet. Владелец хранит файл учётных данных вне репозитория в режиме 0600. Ожидаемые имена полей — session_private_key, session_signer, deposit_wallet, api_key, api_secret и api_passphrase. Пути через символические ссылки запрещены. Значения остаются в изолированном процессе. Пакет polymarket-client версии 0.20.1 закреплён ссылкой на проверенный файл и его SHA‑256. Источник имени пакета — [документация Python SDK](https://docs.polymarket.com/getting-started/python).

Приватный каталог состояния на Mac — ~/.local/state/polymarket-lab/canary/ в режиме 0700. В нём размещаются orders.sqlite3, STOP и allowlist.json. Список разрешений — файл 0600 с JSON-массивом объектов, в каждом строки condition_id и token. Для постановки нужны подтверждённые публичные котировки и разрешение геопроверки. Реестр резервирует деньги на диске перед единственной попыткой отправки и учитывает частичные исполнения по подтверждённому состоянию.

После потери ответа на постановку повтор с тем же идентификатором автоматически заявку не отправит. Если внешний номер известен, команда cancel с исходным --request-id сверяет состояние и снимает эту заявку. Если номер неизвестен, запись сохраняет весь резерв. Владелец сверяет историю заявок и исполнений на площадке. Истечение срока заявки само по себе не доказывает отсутствие исполнения. Сохранение оригинальной базы необходимо для учёта дневного убытка.
