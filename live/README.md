# Живая лаборатория

Команды выполняются в корне клона polymarket-lab. Рабочее окружение проверено на Python 3.12. Большие файлы остаются в data/live/ на этом компьютере.

```sh
python3.12 -m venv live/.venv
. live/.venv/bin/activate
python3 -m pip install -e . -r live/requirements.txt
python3 -m pytest -q tests live/
python3 -I live/doctor.py
caffeinate -i python3 -m live.record record --seconds 7320
python3 -m live.record status
```

У каждой записи своя папка с UTC-временем старта. Настройки рынков лежат в live/markets.json. Регистратор подписывается на текущие и следующие окна BTC 5m/15m, температурные корзины Лондона, Парижа и Нью-Йорка и до десяти матчей дня по календарю тенниса (сначала уже начавшиеся). Он получает стаканы, изменения уровней и публичные сделки. В тех же файлах сохраняются доступные в момент наблюдения закрытые секундные свечи BTCUSDT и официальные выплаты по завершившимся рынкам.

Каждая строка содержит время приёма на Mac в наносекундах и локальный порядковый номер. Это время получения сообщения приложением. Если время в данных площадки отличается, сохраняются обе отметки. Данные сжимаются блоками; завершённая минута получает окончательное имя после сброса на диск. Статус отражает подтверждённые сервером PONG, сетевые ошибки и сверки. Оставшаяся после аварии часть .open может быть неполной. Команда validate проверяет запечатанные минуты и считает по каждому полностью записанному окну BTC долю времени с пригодной глубиной для каждого исхода. Снимок, полученный до начала окна, учитывается лишь пока соответствующий стакан остаётся доступен.

```sh
python3 -m live.validate "$RUN_DIR" --minimum-seconds 7200
python3 -m live.book as-of "$RUN_DIR"/*.jsonl.gz --token "$TOKEN" --recv-ns "$AT_NS" --depth 3
python3 -m live.book coverage "$RUN_DIR"/*.jsonl.gz --token "$TOKEN"
```

Для команд выше RUN_DIR — папка конкретного сеанса, TOKEN — публичный идентификатор исхода из строки market, AT_NS — интересующий момент в Unix-наносекундах. Внутри интервала потери связи цена помечается недоступной. Изменение биржевого времени назад, несовпадение глубины и отсутствие начального снимка также закрывают покрытие. Новый пригодный полный снимок восстанавливает его. Для неподвижной книги используется подтверждение связи. В активном стакане сверка REST учитывается только когда за время запроса не поступало изменений этого токена. Площадка не предоставляет сквозного номера своих сообщений, поэтому отдельная пропущенная и затем компенсированная дельта может остаться ненаблюдаемой. Описанные проверки измеряют покрытие, которое можно доказать из записи.
